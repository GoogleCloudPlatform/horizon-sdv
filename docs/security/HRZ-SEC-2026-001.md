# HRZ-SEC-2026-001: Predictable Gerrit Admin HTTP Password

**Severity:** Critical
**Affected:** All deployments and sub-environments that still use the default `gerrit-admin` HTTP password. The predictable password was first introduced on the public repository in commit [`6bab307`](https://github.com/GoogleCloudPlatform/horizon-sdv/commit/6bab307) (Release 3.0.0) and is still present in the last tagged release, HORIZON_RELEASE_4.3.0.

> **Affected versions:** HORIZON_RELEASE_3.0.0 (2026-01-13) → HORIZON_RELEASE_4.3.0 (2026-10-07), the last tagged release where the issue is present

**Component:** `gerrit-post` job ([`terraform/modules/sdv-container-images/images/gerrit/gerrit-post/configure.sh`](https://github.com/GoogleCloudPlatform/horizon-sdv/blob/6bab307/terraform/modules/sdv-container-images/images/gerrit/gerrit-post/configure.sh))

## Summary

The HTTP password for the Gerrit `gerrit-admin` account is not random. The `gerrit-post` job sets it to the first 30 characters of the second line of the account's OpenSSH private key:

```bash
httpPassword=$(cat /root/.ssh/privatekey | head -2 | tail -1 | cut -c1-30)
```

For an unencrypted OpenSSH key, those characters encode only the fixed file header (`openssh-key-v1`, cipher `none`). They contain no key material. Every Horizon deployment therefore has the **same** `gerrit-admin` HTTP password, and anyone who has read this code or generated an OpenSSH key can work it out.

## Impact

`gerrit-admin` is a member of the Gerrit Administrators group. Gerrit accepts the HTTP password for the REST API (`/gerrit/a/...`) and git over HTTPS. Both are reachable on the public Horizon domain with no further restriction. An unauthenticated attacker on the internet can:

- **Take over the account:** change its HTTP password, add their own SSH keys, and lock out Jenkins and the Gerrit MCP server.
- **Administer Gerrit:** add users to Administrators, change permissions on any project, and create or delete projects.
- **Change source code:** push directly or force-push to any branch, and approve and submit their own changes.
- **Run code in the cluster:** upload a change to an `android/*` project and vote `Ready-for-Build +1`. Jenkins then builds the change in a privileged pod running as `jenkins-sa`. Through Workload Identity that account has project-wide roles including `roles/editor`, `roles/container.admin` and `roles/resourcemanager.projectIamAdmin`. This leads to full control of the GKE cluster, every Secret Manager secret, and the ability to make itself owner of the GCP project.

## Check if you are affected

Try to clone a repository as `gerrit-admin` using the predictable password (replace `<domain>`):

```bash
git clone https://gerrit-admin:b3BlbnNzaC1rZXktdjEAAAAABG5vbm@<domain>/gerrit/a/All-Projects
```

The password `b3BlbnNzaC1rZXktdjEAAAAABG5vbm` is the same on every affected deployment. A successful clone means the account is exposed. `Authentication failed` means it has already been rotated.

## Fixes for deployed systems

### Immediate mitigation

Run `HRZ-SEC-2026-001.sh` with kubectl pointed at the affected cluster:

```bash
DRY_RUN=1 ./HRZ-SEC-2026-001.sh <domain>   # checks only
./HRZ-SEC-2026-001.sh <domain>
```

The script:

- sets a random 32-character password on `gerrit-admin`;
- writes it into `jenkins/jenkins-gerrit-http-password` and `gerrit/gerrit-http-password`;
- restarts `gerrit-mcp-server`.

Jenkins picks up the new value from the secret. Afterwards the old password must return HTTP 401. Set `NAMESPACE_PREFIX` for sub-environments and repeat for each one.

**Caveat:** rotation does not persist. As shipped, `gerrit-post` resets the password to the predictable value whenever the job runs again. This includes a Terraform run that rebuilds the `gerrit-post` image, a version bump of that image, any change to files in its Docker context (including `configure.sh` itself), a destroy and recreate, or an ArgoCD resync that recreates the job. Avoid changes that re-trigger `gerrit-post` unless you are ready to re-rotate. After any such event, rerun the rotation, or patch `configure.sh` to generate a random password and rebuild the `gerrit-post` image for a durable fix.

### Longer-term patch

Make the fix permanent in `terraform/modules/sdv-container-images/images/gerrit/gerrit-post/configure.sh`. Replace the private-key slice:

```bash
    local httpPassword
    # HTTP password logic: add debug with date/time here (no masking)
    httpPassword=$(cat /root/.ssh/privatekey | head -2 | tail -1 | cut -c1-30)

    if [ "$httpPassword" != "$HTTP_PASSWORD" ]; then
      HTTP_PASSWORD=$httpPassword
      echo "WARNING: HTTP passwords differ or 1st time setup."
    fi
```

with a random password generated only when none is already stored:

```bash
    # First run has no stored password. Later runs keep jenkins-gerrit-http-password.
    if [ -z "${HTTP_PASSWORD}" ]; then
      HTTP_PASSWORD=$(LC_ALL=C tr -dc 'A-Za-z0-9' < /dev/urandom | head -c 32)
      echo "Generated a new gerrit-admin HTTP password."
    fi
```

`HTTP_PASSWORD` is already loaded from `jenkins-gerrit-http-password` earlier in the script, so reruns keep the existing value instead of overwriting it. Also quote the value when encoding so a special character is not split:

```bash
      HTTP_PASSWORD_BASE64=$(printf '%s' "$HTTP_PASSWORD" | base64 -w0)
```

Rebuild and publish the `gerrit-post` image. The first deployment after this change generates a random password and preserves it on every later run.
