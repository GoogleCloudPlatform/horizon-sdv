# Phase 2: Terraform Configuration from the Sample

This guide details how the agent prepares `terraform/env/terraform.tfvars` from `terraform/env/terraform.tfvars.sample` and minimal user inputs (`GCP_PROJECT_ID` and `ROOT_DOMAIN`). The result is the same file a user would create by following `docs/deployment_guide.md`, so `deploy.sh` and `container-deploy.sh` behave exactly as documented.

---

## 1. Minimal Questionnaire

The agent prompts the user only for:
1. **`sdv_gcp_project_id`**: Target Google Cloud Project ID.
2. **`sdv_root_domain`**: Target root domain (e.g. `example.com`).
3. **`scm_auth_method`**: `userpass` (sample default), `app`, or `none` (public repositories only). For `userpass`, also ask for `scm_username` and `scm_password`.

---

## 2. Parameter Sources

Copy `terraform/env/terraform.tfvars.sample` to `terraform/env/terraform.tfvars`, then fill only these values. Every other value keeps its sample default.

| Variable | Source | Value |
| :--- | :--- | :--- |
| `sdv_gcp_project_id` | User | Questionnaire |
| `sdv_root_domain` | User | Questionnaire |
| `sdv_gcp_backend_bucket` | Derived | `"<GCP_PROJECT_ID>-horizon-tfstate"` (created in Phase 1) |
| `sdv_gcp_compute_sa_email` | Derived | `<PROJECT_NUMBER>-compute@developer.gserviceaccount.com` (queried via `gcloud`) |
| `sdv_env_name` | Proposed | `"dev"` (sub-domain / environment name) |
| `scm_repo_url` | Derived | `git config --get remote.origin.url` |
| `scm_repo_branch` | Derived | `git rev-parse --abbrev-ref HEAD` (must exist on the remote) |
| `scm_auth_method` | User | Questionnaire |
| `scm_username`, `scm_password` | User | Only for `userpass`; for `none` or `app`, set `scm_password = "unused"` (must be non-empty; stored as `scm-password-b64`) |
| `sdv_keycloak_admin_password` | Generated | See §3 |
| `sdv_keycloak_horizon_admin_password` | Generated | See §3 |
| `manual_secrets.s5` (Argo CD admin) | Generated | See §3 |

> [!IMPORTANT]
> **Review table before writing the file**:
> Present every value of the final file in one table, marking each as *user*, *derived*, *sample default* or *generated* (passwords masked). Point out sample defaults the user is likely to want to change, for example `sdv_gcp_region` / `sdv_gcp_zone`, the ARM64 brownfield block (`enable_arm64_dedicated_subnet`, `arm64_*`), and `sdv_cluster_maintenance_exclusions` dates. Write `terraform/env/terraform.tfvars` only after the user approves.

> [!IMPORTANT]
> **Credential Display Policy**:
> During deployment handoff, only the locally-generated admin passwords (`horizon-admin`, Keycloak `admin`, and Argo CD `admin` from `manual_secrets.s5`) are presented to the user, read from `terraform.tfvars`.
> Service passwords generated by Terraform (Jenkins, Gerrit, Grafana, PostgreSQL, MCP Gateway) are synced directly to workloads via Kubernetes External Secrets and are **not** displayed proactively. They can be queried on-demand from Secret Manager if ever required for emergency/break-glass access:

```bash
# Emergency on-demand fallback password retrieval:
# Jenkins Admin (admin)
gcloud secrets versions access latest --secret="jenkins-admin-password-b64" --project=<GCP_PROJECT_ID> | base64 --decode && echo

# Gerrit Admin (admin)
gcloud secrets versions access latest --secret="gerrit-admin-password-b64" --project=<GCP_PROJECT_ID> | base64 --decode && echo

# Grafana Admin (admin)
gcloud secrets versions access latest --secret="grafana-admin-password-b64" --project=<GCP_PROJECT_ID> | base64 --decode && echo

# PostgreSQL Password
gcloud secrets versions access latest --secret="postgres-admin-password-b64" --project=<GCP_PROJECT_ID> | base64 --decode && echo
```

## 3. Password Generation

`terraform/env/variables.tf` requires at least 12 characters with an uppercase letter, a number and a symbol (Keycloak passwords also need a lowercase letter), and rejects `Change_Me_123`. Generate each password locally and never print it in chat except in the final handoff:

```bash
python3 - <<'EOF'
import secrets, string
symbols = "!@#*-_+="
alphabet = string.ascii_letters + string.digits + symbols
while True:
    p = "".join(secrets.choice(alphabet) for _ in range(20))
    if (any(c.islower() for c in p) and any(c.isupper() for c in p)
            and any(c.isdigit() for c in p) and any(c in symbols for c in p)):
        print(p)
        break
EOF
```

The symbol set avoids `"`, `\`, `$` and `%`, which need escaping in HCL strings (`${` and `%{` start template sequences).

## 4. Sample `terraform.tfvars` (filled values only)

```hcl
# GCP Configuration
sdv_gcp_project_id       = "my-cloud-project-123"
sdv_gcp_region           = "europe-west1"
sdv_gcp_zone             = "europe-west1-d"
sdv_gcp_compute_sa_email = "9876543210-compute@developer.gserviceaccount.com"
sdv_gcp_backend_bucket   = "my-cloud-project-123-horizon-tfstate"

# Environment Metadata
sdv_env_name    = "dev"
sdv_root_domain = "your-domain.com"

# SCM Configuration
scm_type        = "github"
scm_auth_method = "none"
scm_repo_url    = "https://github.com/GoogleCloudPlatform/horizon-sdv"
scm_repo_branch = "main"
scm_username    = "git"
scm_password    = "unused" # must be non-empty; not read when scm_auth_method = "none"

# Required Admin Secrets (generated)
sdv_keycloak_admin_password         = "<GENERATED>"
sdv_keycloak_horizon_admin_password = "<GENERATED>"

manual_secrets = {
  s5 = "<GENERATED>"
}

# All other settings (ARM64, GKE version and maintenance, network policies,
# DNSSEC, KMS, sub-environments) keep their values from terraform.tfvars.sample.
```
