cloud-workstations

Automated, declarative lifecycle management for Google Cloud Workstations development environments directly from Horizon. Workflow submit is not limited by role yet.

Experimental

Any signed-in user can run every Cloud Workstations workflow, including create, delete, and changing who can use a workstation. The Portal does not separate admin and user actions. Your own workstation workflows only show and start workstations that list your signed-in username. Access on the workstation in Google Cloud still follows the users and admins set on it.

Functionality

Provides self-service creation, configuration, and runtime control of Cloud Workstations on Google Cloud Platform:

  • Workstation Lifecycle: Create, start, stop, and delete workstations on demand.
  • Custom Configurations: Manage machine types, container images, persistent home directories, and security posture.
  • Developer Experience: Access web-based IDEs and terminal environments securely through the browser or local tooling.

Dependencies

cloud-workstations requires workloads-common as a hard dependency.

  • workloads-common must be enabled first to provide the required container-image build templates and credential workflows.
  • Module Manager will reject disabling workloads-common while cloud-workstations is active.
  • Before any other workflow, run cws-image-build once per environment with buildEnvironmentImage=true, imageTag=latest, and every other image off. Until then, the other workflows stay Pending.

Disable Behavior

When this module is disabled in Module Manager, an automated teardown is executed:

  • All active workstations and workstation configurations are terminated and deleted.
  • The underlying Cloud Workstations (CWS) cluster in Google Cloud is deleted along with the module's Kubernetes namespaces.
Resource Deletion Warning Disabling the module deletes the CWS cluster and any non-persistent workstation data. Ensure code and artifacts are committed and pushed before turning off the module.
